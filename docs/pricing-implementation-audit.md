# Pricing audit — before allowance selection

Inspected review HEAD 45d4091 and the complete Phases 1–7 stack. Production main is still 075dcaa. At the inspected baseline, no PayPal, subscriptions, checkout, commercial entitlement or paid receipt implementation existed. No Google OAuth flow exists: verified email/password, confirmation, recovery and server-side cookie sessions are implemented and will be preserved.

Available code: three reference-edit modes (personal/portrait/product), private JPEG/PNG/WebP uploads normalized to WebP, original/result comparison, download, product-preservation controls, local quality checks and optional metered AI assessment, controlled retries, five-view packs, Brand Studio/logo compositing, durable bulk orchestration, image library, folders/archives/30-day photo recovery. All await pending hosted migrations/configuration and real funded provider verification. No video, native 4K offer, teams, API product, priority support or guaranteed fidelity exists.

AI resource operations: one Images edit per generated output; optional one vision assessment per product output; separately requested quality retries are new charged edits from the original. A five-view pack is five edits, a three-source complete batch is fifteen. Uploading, folder changes, original downloads, direct logo compositing and local checks are not provider generations. Definitive pre-dispatch failures/cancellations release reservations; reported usage is checkpointed before storage validation. Unknown paid outcomes remain held and are never replayed automatically. Duplicate submission IDs do not create a second job; safe transport retries are bounded to three.

Actual image default: gpt-image-2.5-sunburst-2026-09-08; allowlisted Flare snapshot and gpt-image-1.5 are optional. low/medium/high quality; native 1024×1024, 1536×1024 or 1024×1536; WebP/compression100, one original reference. Product vision gpt-6.1-terra, maximum 1500 completion tokens, two downscaled references. Previously inspected official model/pricing snapshots record 2.5 uncached rates $5/text-input, $8/image-input, $30/image-output per million; vision $1 input/$5 output per million. The official pricing markdown was fetched again in this turn on 28 October 2026 and confirmed those standard rates. This verifies published unit rates, not any actual image cost. Rate changes must be reviewed before activation. Existing scripts/docs preserve source evidence. Actual paid image test previously returned exhausted billing credit; no successful provider image or production cost measurements exist. No new funded call is needed for this phase.

Cost is token-dependent, not a fixed price per image. Illustrative assumptions (NOT measurements): 2,000 prompt tokens + 1,000 input-image tokens + 1,000 output-image tokens at those rates ≈$0.048/image, before optional vision. A 4,000-output-token example ≈$0.138. A five-view pack multiplies each distinct output's usage; source size, canvas, quality, assessment and retry can increase it. Production estimates require operator-reviewed model-specific token tables and bounds; cached/batch discounts are not assumed. Existing pack accounting records actual reported token usage, request IDs, per-operation cost estimates, reserved credit holds, settled/released/unknown outcomes. At the baseline standalone jobs had dollar-budget guards but were not on the pack credit ledger; this change extends that same ledger to standalone edits.

Recommended prices: Starter $9/month for 100 processing units, Pro $19/month for 250. One unit is a $0.01 configured provider-cost allowance, not one image. At full nominal consumption those units cover $1/$2.50 respectively, leaving 88.9%/86.8% before payment fees, infrastructure, storage, support, tax, unreported/over-reserve usage and refunds. This is a conservative nominal AI-budget margin, NOT guaranteed profit. Scenario assumptions of 4%+$0.50 fees and a further $1/$2 overhead allowance still leave useful headroom; these fee/overhead numbers are planning assumptions, not verified merchant costs.

Annual: $90/1200 units and $190/3000 units, charged up front, exactly two months saved (16⅔% against 12 monthly charges). Annual units are granted up front, not fictionally refilled monthly. One-time: $5/50 units or $15/200 units; no renewal. Purchased/granted units do not expire while the account exists: implemented as a single persistent prepaid balance, with no monthly-reset promise. Unused prepaid liability must remain funded; it is not immediately distributable profit. Cancelling stops future billing, keeps the paid-through feature period and retains previously earned units/projects. Verified refunds remove proportional purchased units and can create a negative balance if consumed; this blocks new work. No separate commercial refund-rights promise is invented.

Free: verified-email account, one lifetime low-quality square reference edit within a 20-unit budget, no payment card. No product packs, batch or Brand Studio generation. No automatic vision fee. Global free-grant admission must be bounded and server-side; existing signup/IP rate protection also remains. If a reviewed low-edit reservation cannot fit the sample budget, generation fails closed rather than silently subsidizing unlimited use. A paid pack retains pay-as-you-go access after subscription cancellation; no browser query parameter grants paid status.

Plan limits are deliberately modest: Starter medium quality and batches up to three sources; Pro high quality and up to five (subject to global caps and existing storage reservations). Free resource caps should be lower. No 20/50/100-source commercial throughput promise: Phase 6 proved 20 tiny-source SQL admission, and 50 hit storage safeguards. No unlimited AI, export count multiplication tricks or unsupported priority/SLA features.

Activation blockers: missing merchant credentials/verified plan IDs and webhook setup, restricted outbound PayPal hosts, missing hosted migrations and real PayPal sandbox/live lifecycle tests, provider funding and token calibration, reviewed legal/tax/customer cancellation/refund disclosures. Keep new purchasing fail-closed and clearly distinguish available registration/selection from unavailable checkout when these are missing. No production merge/deploy is authorized.
